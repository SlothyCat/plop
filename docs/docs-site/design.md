# Documentation Site (Docusaurus) — Design

Status: Approved · Date: 2026-06-30

## Goal

Publish the project's documentation as a Docusaurus site that doubles as a portfolio: it serves
the ~90 existing engineering specs as a **Reference**, wrapped in a curated **Story** that
narrates the brainstorm→plan→execute workflow — with scaffolded "From the author" blanks for the
owner's personal voice. Deployed to GitHub Pages.

## Decisions (approved)

1. **Purpose: both** — a dev-process/architecture site now, with room to grow a user guide later.
2. **Location: `website/` subfolder**, deployed to **GitHub Pages** via a dedicated Actions
   workflow (isolated from the Swift `ci.yml`).
3. **Content: serve the existing `docs/` as-is** with an autogenerated sidebar (no duplication),
   plus curated narrative pages and a custom homepage.
4. **Personal voice: Standard density** (~18 scaffolded blanks) via a reusable `:::voice`
   callout. Tiers 1–3 below.

## Architecture

Docusaurus 3 (classic preset) in `website/`, its own `package.json`/`node_modules`, isolated
from the Swift app. Two docs areas + a homepage:

- **Reference** — the default docs instance, `path: '../docs'`, **autogenerated sidebar** from
  the folder structure. Serves the raw specs. Route base `/reference`.
- **The Story** — a second docs instance (`@docusaurus/plugin-content-docs`, id `story`),
  `path: 'story'` (curated pages authored in `website/story/`), autogenerated sidebar. Route base
  `/story`. Holds the narrative + most personal voice.
- **Homepage** — `src/pages/index.tsx` (or `.js`): hero + a short "Why I built this" voice
  block + cards linking into The Story and Reference.

> If Docusaurus rejects a docs `path` outside the site dir (`../docs`), the fallback is a
> committed symlink `website/reference-docs -> ../docs` (or a build-time copy step). The plan
> verifies the direct path first.

## Key configuration

- `markdown: { format: 'detect' }` — `.md` files (the specs) parse as **CommonMark, not MDX**,
  so prose like `Binding<Color>` or `docs/<feature>/` doesn't break the build. Code fences are
  safe regardless. The curated Story pages may be `.mdx` where richer formatting helps.
- `onBrokenLinks: 'warn'`, `onBrokenMarkdownLinks: 'warn'` — cross-spec links never fail the build.
- Site metadata: `url: 'https://slothycat.github.io'`, `baseUrl: '/plop/'`,
  `organizationName: 'SlothyCat'`, `projectName: 'plop'`, `trailingSlash: false`.
- Admonitions: register the custom keyword — `admonitions: { keywords: ['voice'], extendDefaults: true }`
  on **both** docs instances — so `:::voice` works in curated pages and in the specs.
- Navbar: **The Story** (→ `/story` overview), **Reference** (→ the roadmap spec as entry point),
  GitHub link. Footer: minimal.

## Personal-voice mechanism

A reusable **"From the author"** callout, authored as:
```
:::voice[From the author]
_Prompt the owner replaces with their own words._
:::
```
Styled in `src/css/custom.css` via the generated `.theme-admonition-voice` class — a distinct
accent box (tie to the app's blue `#8CC0EB`), **no emoji** (keeps the project's restrained
aesthetic). Each scaffolded block contains an italic prompt as the blank to fill.

### Distribution (Standard, ~18 blanks)

- **Tier 1 — Anchor (always seen):**
  - Homepage: one "Why I built this" voice block.
  - `story/behind-the-build.mdx`: a dedicated essay with **4–5** prompted voice blocks
    (the workflow, what worked, what was hard, what I'd change, advice).
- **Tier 2 — Section intros (~8):** one curated page per domain under `story/sections/`, each
  with a "My take on this area" voice block + links to the relevant specs. Domains:
  Home & Entry, Insights & Budget, Recurring, Export, Categories·Currency·Theme, Cleanup & Polish,
  Branding (icon/launch), Feedback (haptics + invalid-action).
- **Tier 3 — Milestone reflections (~6):** a `:::voice[Reflection]` block appended to the end of
  these specs (the only edits to `docs/`):
  `settings-export/design.md`, `recurring/sp2-generation-engine/design.md`,
  `donut-min-arc/design.md`, `popup-consistency/design.md`,
  `home-entry/design.md` (SwiftData modeling), `haptics/design.md`.
- **Tier 4 — Inline (unlimited):** the owner drops `:::voice` blocks anywhere; documented in a
  short "Adding your voice" note on the Story overview.

## Deployment

`.github/workflows/docs.yml` — on push to `main` touching `website/**` or `docs/**`: Node 20,
`npm ci`, `npm run build`, then the official Pages actions (`upload-pages-artifact` +
`deploy-pages`). Concurrency-guarded. **One manual owner step:** repo Settings → Pages → Source =
"GitHub Actions". Result: `https://slothycat.github.io/plop/`. The Swift `ci.yml` is untouched.

`.gitignore` additions: `website/node_modules`, `website/build`, `website/.docusaurus`.

## Testing

- No unit tests (a docs site). The gate is **`npm run build` succeeds** (catches MDX/link
  issues) locally and in CI.
- Owner check: `npm start` preview — homepage, The Story (essay + section intros + voice boxes
  render distinctly), Reference (specs + sidebar), the 6 milestone reflections; navbar/links work.
- The Swift app build/tests are unaffected (no app or `ci.yml` changes).

## Scope

**In:** `website/` Docusaurus scaffold + config; Reference (../docs) + Story (curated) instances;
homepage; ~8 section intros; the `:::voice` admonition + CSS; ~6 spec reflection appends;
`.gitignore`; the Pages workflow.

**Out:** rewriting/condensing the specs; a real user guide (stub only — the "later" half of
Both); custom domain; versioned docs; search (can add Algolia later).

Single PR: `feature/docs-site`.
